## 改法：加 `resolve.alias` + `optimizeDeps.exclude`

```ts
import { defineConfig, type UserConfig, type ConfigEnv, loadEnv } from "vite";
import uni from "@dcloudio/vite-plugin-uni";
import AutoImport from "unplugin-auto-import/vite";
import { createRequire } from "module";

const require = createRequire(import.meta.url);

export default defineConfig(async ({ mode }: ConfigEnv): Promise<UserConfig> => {
  const UnoCss = await import("unocss/vite").then((i) => i.default);
  const env = loadEnv(mode, process.cwd());

  // 解析 @dcloudio/uni-ui 的真实磁盘路径（跟 pnpm 软链无关，拿到的是真实位置）
  const uniUiRoot = require.resolve("@dcloudio/uni-ui/package.json").replace(
    /[\\/]package\.json$/,
    ""
  );

  return {
    server: {
      host: "0.0.0.0",
      port: +env.VITE_APP_PORT,
      open: true,
      proxy: {
        [env.VITE_APP_BASE_API]: {
          changeOrigin: true,
          target: env.VITE_APP_API_URL,
          rewrite: (path) =>
            path.replace(new RegExp("^" + env.VITE_APP_BASE_API), ""),
        },
      },
    },
    plugins: [
      UnoCss(),
      AutoImport({
        imports: ["vue", "uni-app"],
        dts: "src/types/auto-imports.d.ts",
        eslintrc: {
          enabled: false,
        },
      }),
      uni(),
    ],

    // ↓↓↓ 加这一段 ↓↓↓
    optimizeDeps: {
      exclude: ["@dcloudio/uni-ui"],
    },
    resolve: {
      alias: {
        "@dcloudio/uni-ui": uniUiRoot,
      },
    },
    // ↑↑↑ 加这一段 ↑↑↑
  };
});
```

---

## 改了什么（就 3 件事）

| 改动                                               | 作用                                                         |
| -------------------------------------------------- | ------------------------------------------------------------ |
| `import { createRequire } from "module"`           | 用 Node 原生 require 拿到 uni-ui 的真实路径，不受 pnpm 软链影响 |
| `optimizeDeps.exclude: ["@dcloudio/uni-ui"]`       | 不让 Vite 预构建 uni-ui（预构建会跟软链打架）                |
| `resolve.alias: { "@dcloudio/uni-ui": uniUiRoot }` | easycom 里写的 `@dcloudio/uni-ui/lib/...` 直接指到真实目录，编译器不再自己算相对路径，就不会把 `_` 写成 `-` |

## 如果 alias 不生效怎么办

`vite-plugin-uni` 有时候在生成小程序产物时会绕过 vite 的 resolve（它内部有自己的编译器管线）。如果 build 完搜出来还有 `node-modules`，那就说明 alias 被绕过了——这时候就别跟它耗了，直接走 方案 2（`.npmrc` 加 `public-hoist-pattern`） 或者 方案 3（拷到 `uni_modules/`）。

你先试这个 alias 版本，build 完跑一下验证命令，把结果贴给我 👊
