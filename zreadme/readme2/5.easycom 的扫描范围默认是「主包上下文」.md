你这个现象完全正常，不是 easycom 坏了，是 uni-app 编译到微信小程序时，easycom 对「npm 包里的 uni-ui + 分包页面」支持有边界，你踩的是官方已知坑。

## 为什么「easycom 之前一直不生效，只有放进分包才能找到」

### 1. easycom 的扫描范围默认是「主包上下文」
• `autoscan: true` 只扫 项目根 `components/` 和 `uni_modules/`

• 你用 npm 装的是 `node_modules/@dcloudio/uni-ui/lib/...`

• 在 Vue3 + Vite 项目里，easycom 的 `^uni-(.*)` 规则有时能解析 npm 包，但分包页面编译时，小程序原生不支持“分包页面反向引用主包/npm 全局 easycom 注入的组件”，编译器在生成 `packageC/.../CategoryTree.json` 的 `usingComponents` 时没把 uni-popup 写进去 → 运行时报 `Component is not found in path "node-modules/@dcloudio/uni-ui/lib/..."` 


### 2. 你“放进分包能找到”的本质
你把 `uni-popup.vue` 复制到 `packageC/components/uni-popup/uni-popup.vue` 后：
• 组件变成分包本地组件

• 你在 `CategoryTree.vue` 里 `import ... from "@/packageC/components/uni-popup/uni-popup.vue"` → 显式依赖

• 编译器能分析到，把组件打进分包 → 能跑


但这只是绕过了 easycom，不是 easycom 修好了。

### 3. 为什么 easycom 在分包里“时灵时不灵”
• 主包页面用 `<uni-popup>` → easycom 注入 → 正常

- 分包页面用 `<uni-popup>` → 小程序要求分包自己带组件或显式声明 → easycom 没把 `usingComponents` 写进分包 page 的 json → 挂
• 尤其 `@dcloudio/uni-ui/lib/...` 这种 npm 路径，在 mp-weixin 编译产物里会变成 `node-modules/...`（你日志里看到的），分包解析更容易断

## 三种可行方案（按推荐度）

### ✅ 方案 A：分包页面里**继续显式 import 本地副本**（你现在的写法，最稳）
既然 easycom 在你这环境分包不灵，就别跟它死磕：

```
packageC/components/uni-popup/uni-popup.vue
packageC/components/uni-popup-dialog/uni-popup-dialog.vue
```
`CategoryTree.vue`：
```js
import uniPopup from "@/packageC/components/uni-popup/uni-popup.vue";
import uniPopupDialog from "@/packageC/components/uni-popup-dialog/uni-popup-dialog.vue";
```
> 注意：你本地这份 `uni-popup` 不能内部再 `import '@dcloudio/uni-ui/...'`，否则还是断。要从 `node_modules/@dcloudio/uni-ui/lib/uni-popup/` 把整个文件夹原样抄过来（包括它依赖的 `uni-transition`、`uni-icons` 等），不然弹窗动画/图标会缺。

优点：分包独立、不依赖 easycom、打包不丢。
缺点：uni-ui 升级时要手动同步。

---

### ✅ 方案 B：把 uni-ui 走 `uni_modules` 方式 + 开分包优化（官方推荐给 mp-weixin）
1. 删掉 npm 的 `@dcloudio/uni-ui`
2. 用 HBuilderX 「插件市场 → uni-ui → 导入到 uni_modules」或手动放：
```
uni_modules/uni-ui/components/uni-popup/uni-popup.vue
uni_modules/uni-ui/components/uni-popup-dialog/...
```
3. `pages.json`：
```json
"easycom": {
  "autoscan": true,
  "custom": {
    "^uni-(.*)": "@/uni_modules/uni-ui/components/uni-$1/uni-$1.vue"
  }
}
```
4. `manifest.json` → `mp-weixin`：
```json
"mp-weixin": {
  "optimization": { "subPackages": true },
  "usingComponents": true
}
```
5. 删 `dist/dev/mp-weixin` 全量重编

这样 easycom 扫 `uni_modules`，部分 CLI 版本在分包里能正确写入 usingComponents。

> 但实话：Vue3+Vite 项目这招也不是 100% 灵，取决于 `@dcloudio/vite-plugin-uni` 版本。

---

### ✅ 方案 C：分包里也写一份 easycom 规则（不推荐，治标）
在 `pages.json` 的 `easycom.custom` 加：
```json
"^uni-(.*)": "@dcloudio/uni-ui/lib/uni-$1/uni-$1.vue"
```
如果主包已经配了这条但还是分包挂，说明编译器没把规则应用到分包 json，加这条也没用，别浪费时间。

---

## 给你最直接的决定

> 你现在是“分包页面 + Vue3 + npm 版 @dcloudio/uni-ui + easycom 不生效”这个组合，官方组合下就是容易挂。
> 不想再调试 easycom：保持你现在“分包本地放 uni-popup 系列 + 显式 import”的写法，把 uni-popup 依赖的子组件也一起抄全，这是生产环境最稳的。
> 想彻底干净：切到 `uni_modules` 安装 + 开 `mp-weixin.optimization.subPackages`，重编试一次，还不行就回退到方案 A。
