明白，你不想用 `shamefully-hoist=true`把所有东西平铺到根目录——确实，那会把 pnpm 严格隔离的优势全干掉，根 `node_modules`会非常脏。

那我们换个思路，**只解决 uni-app 编译时的路径问题，不破坏 pnpm 的隔离结构**。

------

## 方案：用 `vite.config.ts`的 alias 拦截

在 `vite.config.ts`里把 `@dcloudio/uni-ui`的引用直接 alias 到正确位置，这样 `vite-plugin-uni`在生成小程序产物时就不会自己去算相对路径了：

```
import { defineConfig } from 'vite'
import uni from '@dcloudio/vite-plugin-uni'
import path from 'path'

export default defineConfig({
  plugins: [uni()],
  resolve: {
    alias: {
      // 把 uni-ui 的引用直接指到 pnpm 的 virtual store 里的实际位置
      '@dcloudio/uni-ui': path.resolve(__dirname, 'node_modules/.pnpm/@dcloudio+uni-ui@版本号/node_modules/@dcloudio/uni-ui'),
    },
  },
})
```

但这样写死 virtual store 路径太脆了（版本一升级就断）。更好的写法：

```
import { defineConfig } from 'vite'
import uni from '@dcloudio/vite-plugin-uni'
import { createRequire } from 'module'

const require = createRequire(import.meta.url)

export default defineConfig({
  plugins: [uni()],
  resolve: {
    alias: {
      '@dcloudio/uni-ui': require.resolve('@dcloudio/uni-ui/package.json').replace('/package.json', ''),
    },
  },
})
```

这样 alias 指向的是 **Node.js resolve 出来的真实路径**，不管 pnpm 怎么放都能找到。

------

## 但说实话——这个方案也有坑

`vite-plugin-uni`在生成小程序产物时，alias 有时候会被绕过（它内部有自己的 resolve 逻辑）。如果 alias 不生效，产物里还是 `node-modules/`。

------

## 真正靠谱且不破坏隔离的方案

### ✅ 用 `public-hoist-pattern`只提升 uni-app 相关的包

在 `.npmrc`里**不用** `shamefully-hoist=true`，只加这几行：

```
public-hoist-pattern[]=@dcloudio/*
public-hoist-pattern[]=uni-*
```

效果：

- 

  ✅ 只有 `@dcloudio`开头的包和 `uni-`开头的包会被提升到根 `node_modules/`

- 

  ✅ pnpm 的严格隔离对**其他所有包**依然生效

- 

  ✅ `vite-plugin-uni`能正常找到路径，不会拼错 `node-modules`

- 

  ✅ 根 `node_modules`不会乱，只多了十来个 uni 相关的包

然后：

```
Remove-Item -Recurse -Force node_modules
Remove-Item pnpm-lock.yaml
pnpm install
Remove-Item -Recurse -Force dist
pnpm build
```

## 对比一下

| 方案                                 | 根 node_modules 干净？ | 解决路径问题？    | 推荐度 |
| ------------------------------------ | ---------------------- | ----------------- | ------ |
| `shamefully-hoist=true`              | ❌ 全平铺               | ✅                 | 不推荐 |
| `public-hoist-pattern[]=@dcloudio/*` | ✅ 只提升 uni 相关      | ✅                 | ⭐⭐⭐⭐⭐  |
| vite alias                           | ✅ 不动结构             | ⚠️ 可能不生效      | ⭐⭐     |
| 手动改 dist                          | ✅                      | ❌ 每次 build 覆盖 | ❌      |

------

## 建议

就用 `public-hoist-pattern`只提升 `@dcloudio/*`和 `uni-*`，这是 **uni-app 官方文档推荐的做法**，既解决了编译器路径问题，又保持了 pnpm 的隔离优势。

你现在的 `.npmrc`里有没有已经配过 `public-hoist-pattern`？贴出来我帮你看有没有冲突，然后直接加上去重装 👍
